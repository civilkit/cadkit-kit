# Translating the UI

All user-visible text comes from message catalogues. English is the source of truth and the fallback; a new language
is one more catalogue and never touches component code. Only English ships today.

## How it works

- `@kit/i18n` holds the catalogues and `t(key, params?, fallback?)`.
  - `{name}` placeholders are filled from `params`.
  - A message can be a string or plural forms (`{ one: '{count} op', other: '{count} ops' }`); the form is chosen with
    `Intl.PluralRules` for the active language.
  - A missing key falls back to English, then to the key itself (or to the `fallback` argument), and is listed by
    `missing()` so a test or a translator can see it.
- `locale` is a signal. Changing it re-renders the app, because the app reads it.
- English catalogues: `packages/ui/src/locales/en.ts` (shared components, keys `ui.*`) and
  `apps/cad/src/locales/en.ts` (the app, keys `app.*`, `cmd.*`, `tab.*`, `group.*`, `layer.*`, `settings.*`,
  `history.*`, `feature.*`, `samples.*`).

## Add a language

1. Copy the two English files to `de.ts` (for example) next to them and translate the values. Keep the keys and the
   `{placeholders}`. A partial file is fine: missing keys show English.
2. Register it before the app starts: `registerCatalog('de', de)` (one line per file).
3. It then appears in Settings, Language, and is remembered per user.

Plural keys need the forms your language uses (`one`, `few`, `many`, `other`...).

## Rules for code

- No literal user-visible text in components: use `t('...')`. Command labels are built at render time so they follow
  the language.
- Ids that code compares (tab ids, group ids, feature type ids) are never translated; the display name is looked up
  with `t('tab.' + id, undefined, id)`.
- Do not build sentences by joining pieces; use one message with placeholders so word order can change.
- User data (part names, feature names, sketch labels) is never translated.
- Numbers, dates and units go through `Intl` and the units code, not the catalogue.

## Testing

- `en-XA` is a pseudo-locale (available in development builds in Settings, Language): it accents and pads English
  inside `[!! ... !!]`, so any text still hard-coded in English or any clipped layout is visible immediately.
- `apps/cad/src/i18n.test.ts` checks that every literal key passed to `t()` exists in English, that the dynamic key
  families are complete, that no command label is a raw key, and that every kernel feature type has a display name.

## Known gaps

- Error and hint text from the kernel session (for example "F1 is still referenced by F2") is English text built in
  the session package. The kernel returns structured codes and parameters, so the app should map `code` to a
  catalogue message (`hint.<code>`) with the parameters; that mapping is not written yet.
- The agent-facing guide and MCP texts stay English.
- Right-to-left layout is not handled yet.
- CivilKit has its own `@civilkit/i18n`. The two should converge on one package; the catalogue format here (flat
  keys, plural objects, English fallback) was chosen to match theirs closely.

## Automatic checks, key scheme, baseline

### Adding a string
1. Add `'area.thing': 'Text with {placeholders}'` to the catalogue next to the code: `apps/cad/src/locales/*.ts` (app), `packages/ui/src/locales/en.ts` (ui package), `apps/cad/src/files/strings.ts` (files).
2. Use `t('area.thing', { name })` in the component. Plurals: `{ one: '...', other: '...' }` and pass `count`.
3. `npm run i18n:check`.

### Key naming
`<area>.<thing>[.<detail>]`, lower camel case segments (`settings.sketch.snap.grid`). Feature enum values shown in the feature editor: `ui.editor.value.<enumKey>.<value>` where `enumKey` is the `ENUMS` key in `packages/ui/src/FeatureEditor.tsx` (`end`, `op`, or `<featureType>.<field>` such as `plane.mode`). Adding a value to `ENUMS` without a label key fails the check; a value with no label at runtime is shown humanised ("Three points") and logs `[i18n] missing enum label`, never raw.

### Dynamic keys
`t(\`prefix.${x}\`)` and `t('prefix.' + x)` cannot be checked statically. Each one must be listed in `tools/i18n_dynamic.json` as `"<template or prefix+>": [every full key it can produce]`. The check fails if a call site is not listed or a listed key is not in `en`. Seed a new entry with `node tools/i18n_check.mjs --bootstrap-dynamic` (regenerates the whole file from current keys; review the diff) or edit by hand.

### What runs where
- `node tools/i18n_check.mjs` (`npm run i18n:check`), about 0.2 s: duplicates, keys used by `t()` exist, dynamic keys, locale files (`locales/<code>.ts`) have no keys outside `en` and matching `{placeholders}` (missing translations are warnings), editor enum labels, unused `en` keys (warning), hardcoded JSX strings (ratchet), writes `tools/i18n_report.txt`.
- `--fast`: skips the unused and hardcoded scans. This is the pre-commit hook.
- `apps/cad/src/i18nCheck.test.tsx` (part of `npx vitest run`): runs the full check, and renders the feature editor for every feature type and every enum value (from the kernel's `part-model` schema plus `ENUMS`), failing if any visible text is a raw enum value, a raw camelCase identifier or looks like an unresolved key.

### Hardcoded-string ratchet
The scan flags text inside JSX children and `title/aria-label/placeholder/alt` attributes (single-line heuristic). `tools/i18n_baseline.json` holds the allowed count per file; the check fails when a file goes above it. After removing strings run `npm run i18n:baseline` to lower the numbers (never raise them to get a commit through; use `t()`). A false positive can be avoided by moving the text to the catalogue or, for a unit or symbol, by extending `UNIT_OK` in the script.

### Pre-commit hook
`npm run hooks:install` (sets `core.hooksPath` to `.githooks` for this clone).

### Not caught
Strings built in non-JSX code (`label: 'Save'`, error messages, `alert`), multi-line JSX text that is not alone on its line, text assembled by concatenation, `t(variable)` where the variable comes from data (only found as unused-key false negatives), dynamic key variants not listed in `tools/i18n_dynamic.json`, and translation quality.
