# Translating the UI

All user-visible text comes from message catalogues. English is the source of truth and the fallback; a new language
is one more catalogue and never touches component code. Only English ships today.

## How it works

- `@kit/i18n` holds the catalogues and `t(key, params?, fallback?)`.
  - `{name}` placeholders are filled from `params`.
  - A message can be a string or plural forms (`{ one: '{count} op', other: '{count} ops' }`); the form is chosen with
    `Intl.PluralRules` for the active language.
  - A missing key falls back to English, then to the key itself (or to the `fallback` argument), and is listed by
    `missing()` so a test or a translator can see it.
- `locale` is a signal. Changing it re-renders the app, because the app reads it.
- English catalogues: `packages/ui/src/locales/en.ts` (shared components, keys `ui.*`) and
  `apps/cad/src/locales/en.ts` (the app, keys `app.*`, `cmd.*`, `tab.*`, `group.*`, `layer.*`, `settings.*`,
  `history.*`, `feature.*`, `samples.*`).

## Add a language

1. Copy the two English files to `de.ts` (for example) next to them and translate the values. Keep the keys and the
   `{placeholders}`. A partial file is fine: missing keys show English.
2. Register it before the app starts: `registerCatalog('de', de)` (one line per file).
3. It then appears in Settings, Language, and is remembered per user.

Plural keys need the forms your language uses (`one`, `few`, `many`, `other`...).

## Rules for code

- No literal user-visible text in components: use `t('...')`. Command labels are built at render time so they follow
  the language.
- Ids that code compares (tab ids, group ids, feature type ids) are never translated; the display name is looked up
  with `t('tab.' + id, undefined, id)`.
- Do not build sentences by joining pieces; use one message with placeholders so word order can change.
- User data (part names, feature names, sketch labels) is never translated.
- Numbers, dates and units go through `Intl` and the units code, not the catalogue.

## Testing

- `en-XA` is a pseudo-locale (available in development builds in Settings, Language): it accents and pads English
  inside `[!! ... !!]`, so any text still hard-coded in English or any clipped layout is visible immediately.
- `apps/cad/src/i18n.test.ts` checks that every literal key passed to `t()` exists in English, that the dynamic key
  families are complete, that no command label is a raw key, and that every kernel feature type has a display name.

## Known gaps

- Error and hint text from the kernel session (for example "F1 is still referenced by F2") is English text built in
  the session package. The kernel returns structured codes and parameters, so the app should map `code` to a
  catalogue message (`hint.<code>`) with the parameters; that mapping is not written yet.
- The agent-facing guide and MCP texts stay English.
- Right-to-left layout is not handled yet.
- CivilKit has its own `@civilkit/i18n`. The two should converge on one package; the catalogue format here (flat
  keys, plural objects, English fallback) was chosen to match theirs closely.
