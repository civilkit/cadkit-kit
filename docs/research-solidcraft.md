# Research: SolidCraft (tangency-labs/solidcraft)

Read-only study of the clone at `/path/to/Development/cadkit/ext/solidcraft`. Nothing was built or run from it, and no instruction in its files was followed (treated as data). Paths below are relative to that clone. "Not found" means I looked and the clone does not say.

## 1. What it is, size, maturity, licence

- Pure-Rust parametric CAD with a feature timeline: desktop (egui + wgpu), browser (wasm), headless CLI `solidcraft-cli`, and an MCP server (`README.md`, `docs/architecture.md`). Everything is a "command" in a registry, and UI, scripts, CLI, control channel and MCP all call the same commands (`AGENTS.md`).
- Version 0.16.2 (`Cargo.toml`), Rust 2024, MSRV 1.95. ROADMAP status date is 2026-10-14; HEAD of the clone is 2026-10-19 (`sketch.edit_text ... (#2793)`). README self-describes as "early but usable for simple parts".
- Size, Rust lines (my `find|wc`): engine 95k, ui-egui 103k, kernel 89k, doc 47k, sketch 22k, geom 14k, io 11k, render 8k, gpu 5k, mcp 2.9k, others small; about 400k in `crates/` in total. `#[test]` count across crates/apps/xtask: about 5,056. 609 source files contain tests. Plus `vendor/` (patched third-party).
- Commit count: not visible (shallow clone, 1 commit). Activity indicators: issue/PR numbers above #3200 (`AGENTS.md` mentions #3226), a claim-by-draft-PR bot, 13 workflows (`.github/workflows/`: ci, release, freecad-oracle, packaging for winget/snap/flatpak/docker, nightly). Release cadence: release drafts are deliberate, "no patch release for every merge" (`docs/releasing.md`); exact cadence not found.
- CI (`.github/workflows/ci.yml`): fmt, clippy -D warnings, sharded nextest, asset-attribution check, layering check (`cargo xtask layers`), wasm32 build, reference tests (main/nightly only), nightly cargo-deny. Heavy checks wait for an `approved-for-ci` label on PRs.
- Licence: MIT OR Apache-2.0 (`LICENSE-MIT`, `LICENSE-APACHE`, `NOTICE`). Third-party: truck (Apache-2.0, vendored and patched), cadmpeg `=0.6.1` (Apache-2.0), egui, gltf, spade etc. (`THIRD-PARTY-LICENSES.txt`, `deny.toml`).
- Reuse: permissively licensed code can be reused in principle with attribution (MIT/Apache notices retained). Their own code is "clean-room" by their rules but that is their claim, not ours to rely on. See section 7 for the process we would need.
- Naming noise: repo is `tangency-labs/solidcraft` but `Cargo.toml` / `AGENTS.md` point at `bherbruck/solidcraft`; the kernel replacement is `bherbruck/solidcore` (not in the clone).

## 2. Geometry kernel

- **Third-party base: `truck`** (ricosjp, Apache-2.0): `truck-modeling`, `truck-shapeops`, `truck-meshalgo`, `truck-stepio` (`Cargo.toml` workspace deps). No OpenCascade, no Parasolid. Only `crates/kernel` may import truck (enforced by `cargo xtask layers`); every truck call goes through `solidcraft_kernel::guard` which turns a panic into `KernelError::Internal` (`docs/book/src/dev/kernel.md`).
- **Heavily patched vendored truck** (`vendor/truck-{shapeops,geometry,meshalgo,stepio}`, `vendor/matext4cgmath`, `vendor/README.md`): patches for empty or degenerate intersection curves, robust triangulation of boolean-made faces, deterministic face order, corner selection at vertices several curves end on, seam angle bugs, a hang in a cubic/quartic root solver, boolean face/edge **history** (`and_with_history`), and big speedups (grid pre-search removal, #1038). This is evidence that truck booleans needed continuous repair.
- **Our-own parts on top of truck**: truck has no fillets, chamfers, shell, offset, delete/split/replace face. SolidCraft wrote these (`crates/kernel/src/blend*.rs`, `shell`, `heal.rs`, `fill.rs`, `bridge.rs`, `step_in/`, `step_out.rs`, `iges_in.rs`, `history.rs`), plus a custom display-mesh planner (watertight, shared edge nodes, GPU evaluation, `docs/capabilities.md`).
- **Replacement planned**: `CONTRIBUTING.md` line ~357 says the kernel "is being replaced by solidcore" (`github.com/bherbruck/solidcore`; progress page linked). `docs/mutation-testing.md` says "SolidCraft will move from truck to solidcore (#1597)". The `solidcore` code is not in this clone; I could not read it. Its licence and maturity: not found.
- **B-rep representation** (own, backend-independent, `docs/native-brep.md`, `solidcraft_geom::brep`, schema 2): f64 mm, Z-up; body > shells > vertices/edges/faces with shell-local u32 indices; faces with ordered loops of oriented edge uses. Curves: line, polyline, spline, rational_spline, circle_arc, ellipse_arc, `intersection` (explicit fitted spline plus tolerance). Surfaces: plane, polynomial and rational tensor-product splines, cylinder, cone, sphere, torus, revolution. Resource caps (1,024 shells, 100k items, degree 16, finite and |x| <= 1e12). It is an optional disposable cache in the design container, "not a STEP replacement" and not an editable snapshot. The validator "does not certify watertightness, geometric coincidence or absence of self-intersections".
- **Booleans**: truck-shapeops, with a long retry ladder recorded as diagnostics (`docs/robustness.md`): exact planar fallback, tool nudge (translation/rotation), coincident-face separation, bore offset, finer tessellation passes. Each candidate must pass volume, membership and spatial checks. Retries that can change the result raise a timeline warning. `timeline.inspect` / `doc.inspect` expose `boolean_diagnostics` (strategy and applied displacement). Special case: equal crossing cylinders (`tangent_cylinders.rs`).
- **Fillet/chamfer** (ROADMAP "Known limitations", ~line 336): constant, variable, chord-length, per-edge radius, corner patches, tangent chains, rolling-ball blend for curved-to-curved chains. G2 fillets only for straight edges between planar faces with perpendicular planar ends ("curved faces/edges, sloped ends and corner junctions remain unsupported"). M3 (general fillets/chamfers) is still "in progress", M2 (robust modelling) "in progress".
- **Shell/loft/sweep/draft**: listed as implemented (`docs/features.md`); shell uses an intersection-join convention (sharp inner corners; a rounded join is not the default), oracle cases 44/45 document it. Shell "thicker than a wall" is refused as not-supported-yet (`docs/robustness.md`). Detailed loft/sweep robustness claims: not found beyond oracle cases.
- **Tolerance model**: every kernel tolerance is a fraction of the body's bounding-box diagonal (`docs/perf.md` ~line 659, `Body::size()` cached). Mesh checks use chord tolerance, facet angle, longest side. Oracle: relative 1e-3 on volume and area. Config equality 1e-9 relative/absolute (`docs/configurations.md`). No single published "model tolerance" constant found.
- **How they verify**:
  - Oracle (`docs/oracle.md`, `tests/oracle/*/recipe.json` + `expected.json`, `cargo xtask oracle`): compares body count, volume, area, centre of mass, bbox. **The generated `docs/oracle.md` says 83 / 83 cases pass (62 analytic, 21 FreeCAD 1.1.4)**; README and `capabilities.md` still say the stale "75 of 76 public reference parts". The FreeCAD cases also report max/mean surface distance (about 0.01 / 0.002 mm). FreeCAD runs as an external program (`tools/freecad-oracle/`); analytic scripts are in `tools/oracle-analytic/`. Their own caveat: this "does not establish complete geometric or workflow equivalence".
  - Seeded fuzzer (`solidcraft-cli fuzz`, `fuzz-one --minimise`; `crates/engine/src/fuzz.rs`, `crates/kernel/src/fuzz.rs`): random designs (box/extrude/revolve + joins, cuts, fillets, chamfers, shells, holes, patterns), per-step checks (valid solid, closed oriented shells, every face meshes, volume moves the right way), boolean identity V(A∪B)+V(A∩B)=V(A)+V(B) within 0.2 %. Each seed in its own process with a timeout. Goldens for seeds 0-95 in `tests/robustness/goldens.json` (volume/area 1e-6, exact face/edge/shell counts), with a bless-with-reason workflow.
  - Hostile-input tests for every command, crash reports with replay (`crates/engine`'s crash module, `docs/crash-reports.md`), mutation-testing plan (`docs/mutation-testing.md`), headless UI scenarios.
- **Known gaps** (ROADMAP, `docs/features.md`): general fillets not done; deferred entirely: MESH, FORM/T-splines, surface beyond what solids need (partly done in M8), PCB, Render (partly built anyway), Animation, Simulation, CAM, **Drawings** (only a view-DXF export and "foundations" docs; M11 deferred). Kernel speed is poor on boolean-heavy designs (rover: 3,324 features, 1,395 bodies opens in about 30 s; `docs/perf.md`).

## 3. Import / export

Sources: `README.md`, `docs/capabilities.md`, `docs/step-import.md`, `docs/formats/3mf-face-tags.md`, `docs/features.md` (Files), `crates/io/src/`.

| Format | Import | Export | As what |
|---|---|---|---|
| STEP AP203/AP214/AP242 | yes (own reader `crates/kernel/src/step_in`, from the public standard) | yes, AP242 with body names, colours, components as assemblies; revolved faces as native planes/cylinders/cones/spheres/tori | real B-rep, held as an **Import** base feature (STEP text embedded in the design); assemblies become nested components with one occurrence per placement; later features build on it |
| IGES 5.3 | yes (`iges_in.rs`, restated as STEP then read) | yes, manifold solid B-reps with names and colours | real B-rep; trimmed/bounded surfaces sewn into a solid (open body if they do not close) |
| FreeCAD `.FCStd` | yes via cadmpeg (desktop+CLI only, not wasm) | no | solids only, re-written as STEP AP214; **feature history, sketches, parameters are NOT imported** |
| Rhino `.3dm` | yes via cadmpeg | no | solids only, as above |
| STL (bin/ASCII) | yes | yes | mesh body (render, measure, move, export; solid features need B-rep) |
| OBJ | yes | yes | mesh body |
| 3MF | yes | yes, also `3mf-tagged` (per-triangle B-rep face index attribute in their own namespace, `docs/formats/3mf-face-tags.md`) | mesh body |
| glTF 2.0 (`.glb/.gltf`) | yes (node tree as components, materials as appearances) | not found | mesh body |
| DXF | sketch import (`sketch.insert_dxf`) | sketch export, flat-pattern export, current-view export | 2D sketch geometry |
| SVG | sketch import (`sketch.insert_svg`) | not found | 2D |
| URDF | no | yes (assembly + joints + meshes, `docs/urdf.md`) | |
| `.solidcraft` | native design: ZIP container or plain JSON | same | parametric timeline |
| mesh to parametric | `mesh.convert` reconstructs only closed constant-section parts with planar and circular-cylindrical faces | | |

- **Explicitly NOT supported / limits**: ACIS `.sat/.sab` (cadmpeg `sat` codec disabled), commercial codecs in cadmpeg (f3d, sldprt, inventor, catia, creo, nx) are deliberately not compiled in (`Cargo.toml` comment). SLDPRT and other proprietary part formats: not read. Parasolid (x_t): not found. DWG: not found. STEP: offset surfaces and pcurve-only edges not read. IGES: ruled and offset surfaces, parameter-space-only curves not read. Browser build does not read FCStd/3dm. Mesh import cannot be edited with solid features. Imports never carry a source feature tree (always a base feature).
- **Failure handling / healing for STEP**: files are untrusted (size, entity count, nesting caps; every kernel call under the panic guard). "What cannot be read becomes a warning on the feature (a face left out gives an open body)". No separate repair or healing tool beyond sewing (`sewing` in kernel) and `heal.rs` (coplanar merge). Y-up files handled with the `up:"y"` option; body naming with `names: solid|product|instance`. Imported assemblies are rigid by default (rigid joints), `component.unlock` releases them. STEP round-trip automated in tests ("STEP reopening is automated", ROADMAP). Validation of import against a corpus: "the STEP corpus" mentioned in `vendor/README.md`, corpus contents not found in the clone.

## 4. Model and command design, agent feedback

- **Document**: parametric feature timeline (`crates/doc`), incremental evaluation, persistent naming by kernel history (`docs/book/src/dev/naming.md`): face names like `F2:top#[F2:side:l4,F4:side:l4]`, `F<n>:blend:<edge>`, edges named `<faceA>|<faceB>`; unverified numbering (`#1`, `#2`) flagged "unverified"; unresolved references are reported, not guessed. This replaced earlier geometry-sampling naming for stated reasons ("quietly re-attaches to a different face"). Same idea as our stable face names.
- **Commands**: id `<area>.<thing>[.<variant>]`, about 439 table rows in `docs/features.md` (sketch.*, solid.*, surface.*, sheet.*, plastic, component, joint, config, timeline.*, inspect.*, file.*, doc.*, parameters.*, motion.*, contact.*, material.*, render.*, diagnostics.* ...). Each `CommandSpec` has params doc, enabled-state, JSON `run`. Programmatic calls never open dialogs.
- **Scripts**: `{"commands":[{command, params}, ...]}` JSON, run by `solidcraft-cli run script.json --out part.step`, `eval`, `snapshot`, `commands` (`docs/scripts.md`, 15 lines). A browser command API exists (`docs/browser-api.md`). Selections are by edge midpoint coordinates or face `name`/`point`, not stable ids, for a lot of commands (`body_topology` returns midpoints to pass back to fillet).
- **MCP** (`docs/mcp.md`, `crates/mcp`, 2.9k lines, stdio JSON-RPC, revisions 2024-11-05 to 2025-06-18). Tools: `list_commands`, `execute`, `batch` (stop at first error, rollback via `edit.checkpoint`, optional timings/profile), `inspect_design`, `measure` (bodies or picked items, min/max/centre distance, angles, round-feature fields), `body_topology`, `set_parameter`, `screenshot` (PNG; GPU, software GPU or CPU fallback, camera spec), `export`, `undo`, `redo`, `crash_reports`, `new_design`, `open`, `save`. Resources `solidcraft://design`, `solidcraft://commands`. Tool annotations (read-only/destructive hints) and a file sandbox (allow-listed folders, `--allow-path`). Bridged mode (`--connect`) drives the running GUI over a token-authenticated JSON-lines control channel (`docs/control-protocol.md`: 256-bit token file, 16 MiB request cap, 16 connections). Agent skills in `skills/` (modeling, editing, checking, mechanisms) copy-in for Claude Code.
- **Agent feedback**: failures leave the design unchanged and return the engine message as a tool error (`isError`); `batch` names the failing step index/command/error; per-feature `error`, `warning`, `timing` in `inspect_design`; `boolean_diagnostics`; `measure` as the numeric verification route; screenshots plus `inspect.section`; crash reports with replay. In-app agent chat design in `docs/agent-chat.md` and `docs/design/in-app-agent-chat.md` (not studied in depth). **Not found**: a machine-readable "can/can't do" capability oracle, structured refusal codes with typed hints, or a verify-reply envelope; errors appear to be free-text strings. "Refuses as not supported yet" exists as a convention (`AGENTS.md`: "unfinished feature returns an error 'not supported yet: ...'").
- **Versus ours** (from `rebuild-main/docs/spec-agent-interface.md`, `robustness.md`, `regen-cache.md`): we return structured errors with precise codes and hints (`FeatureError::with("hint", ...)`), budgets (`featureTimeMs`, `regenTimeMs`), a content-keyed regen cache with checkpoint resume, and typed stateless queries (`profiles`, `checkProfile`, `threadData`, `textMetrics`, DOF report). SolidCraft has a content-addressed reuse too ("restored: features whose earlier result for the same inputs was reused", `set_parameter`), but not described as a prefix-keyed full-state cache.

## 5. Sketch, parameters, assemblies, sheet metal, drawings, simulation, text, threads, performance

- **Sketch solver** (own, `crates/sketch`, 22k lines): constructive placement by loci intersection and rigid-cluster decomposition (Owen 1991; Fudos-Hoffmann 1997) plus Levenberg-Marquardt; DOF from Jacobian rank; over-constraining edits are rejected. Constraints: coincident, point-on-curve, H/V, parallel, perpendicular, tangent, curvature (G2), equal, concentric, collinear, midpoint, symmetry, fix; dimensions linear/aligned/H/V/point-line/radius/diameter/angle/arc sweep/arc length/slot length. Geometry: lines, arcs, circles, ellipse, splines (fit/control), conics, slots, polygons, text; trim/extend/offset (associative)/mirror/patterns/projection.
- **Parameters/expressions**: unit-aware expressions (+-*/^, sin/cos/sqrt/min/max/floor/ceil/round, unit conversion), dependency graph with cycle path reporting, rename follows references, CSV/JSON import/export.
- **Configurations** (`docs/configurations.md`): table of rows (parameter expressions + feature suppressions + per-row materials/appearances); `config.activate` all-or-nothing and undoable.
- **Assemblies**: components, occurrences, joints (rigid, revolute, slider, cylindrical, pin-slot, planar, ball) with limits, closed kinematic loops, motion studies, contact sets and interference, mass properties, explode, URDF export.
- **Sheet metal**: base/edge/contour flange, hem, unfold/refold, convert, flat pattern + DXF, bend table, rules (thickness, K-factor, radius). Plastic subset: boss, rib, web, lip/groove, snap fit.
- **Drawings**: deferred (M11). **FEA / simulation**: deferred; only physical material cards, directional elasticity query and motion/contact studies, no solver ("does not provide a solver"). 3MF face tags are explicitly designed for downstream FEA tools.
- **Text/fonts**: sketch text via `ttf-parser` (outlines), engraving/emboss, installed fonts or file paths. **Threads**: cosmetic and modelled, metric M3-M20, internal and external, ISO profile; no tolerance classes, no left-hand threads (ROADMAP).
- **Performance** (`docs/perf.md`, 904 lines, laptop i7-8565U): sensor enclosure open about 3.1 s; hub with radial hole 1.4 s; bicycle frame (union of tilted tubes) 7.2 s; rover (3,324 features, 1,395 bodies) 29.8 s, 2 GB RSS; display meshing of 78 reference bodies about 65 ms (50-65x faster than previous mesher). Boolean edge division was 42-85 % of CPU. Slow kernel is acknowledged and is a driver for the solidcore rewrite.
- **Other**: design container `.solidcraft` = ZIP with `container.json`, `document.json`, content-hashed `blobs/<sha256>.<step|mesh|png|jpeg>`, optional preview cache and optional native B-rep cache, atomic save with `.bak`, autosave recovery (`docs/design-container.md`); i18n catalogs (Japanese etc.), 3D mouse support, plugins design (`docs/plugins.md`), render workspace with CPU PBR.

Where SolidCraft is ahead: breadth (sheet metal, joints/motion, configurations, render, IGES/3MF/glTF/URDF I/O), CI and release maturity, oracle against an external kernel with surface-distance, fuzz goldens with bless workflow, file container with content hashing. Where we look ahead: structured refusals and hints for LLMs, budgets and no-hang guarantees, regen cache design, ownership of the kernel (they depend on a patched truck and admit a rewrite is needed), SLDPRT feature-tree import, wasm-first browser kernel.

## 7. Ideas worth borrowing, risks, recommendation

Ideas (design-level, not code):
1. **Oracle recipe format** (`tests/oracle/NN-name/{recipe.json,expected.json}` with analytic or FreeCAD-computed values, Pappus/Steiner closed forms listed per case, generated table). Cheap to replicate against our kernel for volume/area/COM/bbox, and to add surface-distance vs FreeCAD (as an external program only).
2. **Seeded fuzz + minimiser + goldens with a bless-with-reason rule**, and the boolean volume identity V(A∪B)+V(A∩B)=V(A)+V(B).
3. **Boolean retry ladder reported as diagnostics**, with "warn only when retry can change the result". Fits our structured-refusal philosophy.
4. **3MF with B-rep face tags** (extension attribute, ignored by other readers) - a way to hand FEA/CAM tools face identity; also a candidate way to carry our stable face tags in mesh exports.
5. **Design container**: ZIP, content-hashed blobs, versioned container vs document, optional preview/native caches that are explicitly never authoritative, size/expansion/entry caps, atomic save.
6. **Import as component with product tree preserved**, `up` and `names` options, imported assemblies rigid by default.
7. **MCP details**: path allow-list sandbox, tool annotations, `batch` with rollback to a checkpoint, `verbose:false` compact replies, agent skills shipped in-repo, token-authenticated control channel.
8. cadmpeg (Apache-2.0, `cadmpeg-core/ir/registry =0.6.1`) as an inexpensive FCStd/3dm/STEP-writer path; check its `docs/format-support.md` first. It also has commercial-format codecs (incl. sldprt) that SolidCraft disables, so licence/legal status of those must be checked before we even look at them.
9. Layering enforced by an xtask and `never break wasm` as a CI gate.

Risks:
- **Licence**: their code is MIT OR Apache-2.0, so reuse is allowed with notices, but nothing here has had a licence review for us. truck and cadmpeg are separate Apache-2.0 works (NOTICE obligations; vendored patches are marked `SolidCraft:`).
- **Clean-room contamination**: `AGENTS.md` and `CONTRIBUTING.md` say they never read GPL/LGPL/AGPL code (OpenCASCADE, FreeCAD, SolveSpace, CadQuery/OCP, LibreCAD, QCAD) and never use data produced with commercial CAD. They do run FreeCAD as an external program for oracle values. Our own sources of truth (SLDPRT reading, OCP reference runs in our sweeps) are a different posture; we must not import their oracle `expected.json` blindly if we cannot show its provenance, and we should not copy their behaviour descriptions that mirror vendor tools. Their docs mention commercial products only as compatibility names (`NOTICE`).
- **Do not copy code without a licence review**. In particular do not lift `vendor/truck-*` patches or the blend code without checking that those files carry no foreign headers; icon/asset rows in `ATTRIBUTION.md` have their own terms.
- Their README/oracle count disagreement (75/76 vs 83/83) shows docs lag code; treat capability claims as claims until a test is read.
- Their kernel is explicitly slated for replacement; borrowing kernel algorithms from the truck-based tree has a short shelf life.

Recommendation: treat SolidCraft as a design reference, not a code source. Borrow the verification patterns (oracle recipes, fuzz goldens, boolean identity, diagnostics-as-data), the 3MF face-tag idea, and the container hygiene. Keep our differentiators (structured refusals, budgets, regen cache, SLDPRT tree import). If we want STEP/IGES import quickly, evaluate cadmpeg directly under its own licence rather than via SolidCraft. Revisit when `solidcore` is public and readable.
